## 1. 一句话讲清 FOC

**FOC = 把"三相对称交流量"变成"两个直流量"去控制，再把结果变回三相。**

为什么非要变？因为：
- 电机里的电流是**正弦交流**，频率跟着转速变（3000 rpm、2 对极 → 100 Hz）；
- 而 PI 控制器对**直流**能做到无静差，对**交流**一定有幅值衰减和相位滞后。

所以标准做法是：把交流量"搬到"跟着转子一起转的坐标系里，在那里它变成直流，PI 就能完美工作。

## 2. 三步坐标变换（几何直觉）

```
   三相静止            两相静止            两相旋转（跟着转子转）
   a / b / c    ──►     α / β       ──►      d / q
               Clarke              Park
```

**Clarke**：三相里有 `ia+ib+ic=0`，所以 3 个数只有 2 个自由度，可以用两个正交轴 (α, β) 完整表示。

```
iα = ia
iβ = (ia + 2·ib) / √3
```

**Park**：把 (α, β) 旋转 `θ`（转子电角度），得到跟着转子转的 (d, q)。

```
id =  iα·cosθ + iβ·sinθ
iq = -iα·sinθ + iβ·cosθ
```

**d 和 q 的物理意义**（这是 FOC 的核心）：

| 轴 | 方向 | 管什么 | 表贴式电机（本项目）的取值 |
|---|---|---|---|
| d | 与转子磁极同向 | 励磁/磁场 | `id* = 0`（不浪费电流去励磁） |
| q | 超前 d 90° | **转矩** | `iq*` 由速度环给出 |

转矩公式：`T = 1.5 · p · [ψf·iq + (Ld−Lq)·id·iq]`
表贴式 `Ld ≈ Lq`，第二项为 0 → **`T = 1.5·p·ψf·iq`，转矩与 iq 成正比**。
这就是"控制 iq 就是控制转矩"的由来。本电机 `KT ≈ 0.05 N·m/A`，要 0.33 N·m 就给 6.6 A。

## 3. 一个 PWM 周期（50 µs）里的完整数据流

```
 TIM1 下溢 ──► ADC1/2/3 同步采三相（待实现） ──► JEOC 中断 ─────────────────────────┐
                                                                           │
  ① 读 ADC → 换算电流        ia = (V_PC0 - 1.25) / 0.12                      │
  ② Clarke                  iα, iβ                                          │
  ③ 取角度 θ（霍尔扇区 + 插值）                                              │
  ④ Park                    id, iq          ← 需要 sinθ / cosθ  ★CORDIC      │
  ⑤ 电流 PI                 vd, vq          （id* = 0, iq* 来自速度环）        │
  ⑥ 反 Park                 vα, vβ          ← 复用同一组 sinθ / cosθ          │
  ⑦ SVPWM                   Ta, Tb, Tc                                       │
  ⑧ 写 TIM1->CCR1/2/3                                                        │
                                                                           │
 下一次更新事件，新占空比生效 ◄──────────────────────────────────────────────┘
```

### 每一步对应到你板子上的什么

| 步骤 | 数学 | 硬件/外设 | 量级 |
|---|---|---|---|
| ① 采样 | — | ADC1/2/3 共同硬件触发（待实现） | 采样窗口与耗时待实测 |
| ① 换算 | `(V−1.25)/0.12` | CPU | 30 周期 |
| ② Clarke | 2 乘 1 加 | CPU | ~10 周期 |
| ③ 角度 | 扇区 + `ω·Δt` | 霍尔 EXTI + 定时器 | 每 1.67 ms 校正一次 |
| ④ Park | 4 乘 2 加 + 2 三角 | CPU + ★CORDIC | 20 / 30 周期 |
| ⑤ PI | 2 个 PI | CPU | 40 周期 |
| ⑥ 反 Park | 4 乘 2 加 | CPU（复用 sin/cos） | 20 周期 |
| ⑦ SVPWM | 3 次相电压 + min-max 注入 | CPU | 60 周期 |
| ⑧ 写寄存器 | — | TIM1 CCR1~3 | 10 周期 |

**总预算**：170 MHz 下 50 µs = 8500 周期。当前电流环尚未实现，整链耗时与占用率待实测。
先用软件数学建立基线，再依据整链最坏耗时决定是否接入 CORDIC/FMAC；当前不能推断实际 CPU 余量。

### ⑦ SVPWM 到底在算什么

不用记复杂的矢量公式，等价写法就三行：

```c
// 1) 反 Park 得到的三相电压（两相→三相）
va =  vα;
vb = -0.5f*vα + 0.866f*vβ;
vc = -0.5f*vα - 0.866f*vβ;

// 2) 零序注入：把三相里最大最小的一半拉回中心（这就是 SVPWM 比 SPWM 多 15% 电压的原因）
vmax = max3(va, vb, vc);
vmin = min3(va, vb, vc);
offset = -0.5f*(vmax + vmin);

// 3) 转成占空比
duty_a = 0.5f + (va + offset) / Vdc;   // 再限幅到 [0.05, 0.92]
```

## 4. CORDIC 是什么

**CO**ordinate **R**otation **DI**gital **C**omputer —— 用"移位 + 加法 + 查小表"迭代逼近旋转的一种算法，
1959 年提出，专门在**没有乘法器**的硬件上算三角函数。STM32G4 把它做成了独立硬件：

| 项目 | 规格（DS12288 Rev 6 §3.8） |
|---|---|
| 引擎 | 24 位旋转引擎，圆形 / 双曲两种模式 |
| 模式 | 旋转模式（给角度求 sin/cos）、向量模式（给 x,y 求 atan2/模长） |
| 能算什么 | sin、cos、sinh、cosh、atan、**atan2**、atanh、模长、**sqrt**、ln |
| 精度 | 可编程迭代次数 |
| 接口 | AHB 从机，结果就绪可直接读，**不用轮询也不用中断**；支持 DMA |

**在 FOC 里的用处**：只干一件事——`θ → (sinθ, cosθ)`。
顺便，做无感 FOC 时 `atan2(vα, vβ)` 求角度、`sqrt(vα²+vβ²)` 求幅值，也是它。

**和软件比**：

| 方式 | 大约周期 | 备注 |
|---|---|---|
| `sinf()` / `arm_sin_cos_f32()` | 100~300 | 走 Flash 取指，受 Flash 取指等待影响，有抖动 |
| 查表（Flash 里的正弦表） | 20~40 | 快，但每次访问 Flash 都可能 cache miss，且占 Flash |
| **CORDIC** | 30~60 | 固定延迟、不看 cache、不占 Flash |

**代价**：接口比函数调用麻烦——要写 `CORDIC->WDATA`，等 ready 位，再读两次 `RDATA`（cos 和 sin）。
在 20 kHz 的 ISR 里用它是完全可行的，但**第一版没必要**。

## 5. FMAC 是什么

Filter MAth aCcelerator —— 一个**带地址生成器的乘累加单元**：

| 项目 | 规格（DS12288 Rev 6 §3.9） |
|---|---|
| 乘法器 | 16 × 16 位 |
| 累加器 | 24 + 2 位 |
| 本地存储 | 256 × 16 位（系数 + 状态） |
| 缓冲区 | 最多 3 块（2 进 1 出），支持循环缓冲 |
| 功能 | **FIR、IIR（直接 I 型）**、点积、卷积、相关 |
| 接口 | AHB + DMA，和 CPU 并行跑 |

**和 FOC 的关系**：它不参与矢量控制主链，只做**滤波**。

| 场景 | 用不用 FMAC |
|---|---|
| 电流采样低通 | 板上已有 1 kΩ + 1 nF 硬件 RC，够了 |
| iq 反馈给速度环的平滑 | 可以用，二阶 IIR |
| 转速微分（霍尔扇区测速噪声大） | 很适合，FIR 微分 + 平滑 |
| 陷波器（抑制机械共振） | 很适合 |

---

## 6. 结论：现在该用什么

| 阶段 | 三角运算 | 滤波 | 理由 |
|---|---|---|---|
| 第一版：跑通 20 kHz 电流环 | `arm_sin_cos_f32()` | 不用 | 先保证逻辑对；CORDIC 会引入新的寄存器时序 bug |
| 第二版：量周期、看抖动 | 换成 CORDIC | — | 用 `DWT->CYCCNT` 对比前后，数据说话 |
| 第三版：加无感/观测器 | CORDIC 的 atan2 必须用 | FMAC 做观测器里的滤波 | 这时 CPU 才真的吃紧 |

判据（不要凭感觉优化）：
- ISR 实测 > 5000 周期，或
- PWM 想上到 30~40 kHz，或
- 加了观测器/弱磁，或
- 实测 ISR 周期抖动 > 5%

四条都不满足 → CORDIC 只是"玩一玩"，不影响能不能转。

---

## 7. 一句话总结

> FOC 的主链是：**采电流 → Clarke → Park → PI → 反 Park → SVPWM → 写 CCR**，
> 其中 Park/反 Park 需要 `sinθ/cosθ`（CORDIC 加速），
> 滤波（FMAC）是可选的旁路，
> 而**角度 θ 从哪来**（霍尔/编码器/观测器）才是真正决定方案难度的那一步。
