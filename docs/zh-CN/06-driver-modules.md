# 06 驱动模块说明（v0.1）

[English](../en/06-driver-modules.md) | **简体中文** | [文档目录](../README.md)

本文对应当前 src 模块。CubeMX 外设初始化完成后由 app_init 组装调用；Core 只在 USER CODE 区接入应用和故障关断。

当前仅支持 G474：应用通过 app_board 获取板级参数；电流和母线 ADC 实现在 platform，接口保留在 src/drv。

## 1. PWM 驱动：tim_pwm

| 接口 | 功能与约束 |
|---|---|
| `pwm_init()` | 关桥、停止输出、占空比清零 |
| `pwm_start()` | 关桥状态下复位计数并提交预装载，再使能六路输出、MOE 和计数器 |
| `pwm_check_ready()` | 三相自检，必须六路成对使能 |
| `pwm_set_duty(du,dv,dw)` | FOC 用，钳位 5%～92% |
| `pwm_set_duty_raw(du,dv,dw)` | 六步用，允许低相 0%，上限 92% |
| `pwm_phase_enable(phase,en)` | 只切换该相 CCxE/CCxNE，不停止计数器 |
| `pwm_bridge_enable(en)` | 三相开桥或无条件关桥；返回 1 成功、0 拒绝 |
| `pwm_bridge_enable_sixstep(high,low)` | 指定两相成对使能、第三相悬空才开桥；返回 1 成功、0 拒绝且已关桥 |
| `pwm_bridge_is_enabled()` | 读取桥使能的软件影子，不代表硬件过流锁存已解除 |
| `pwm_stop()` | 先关桥，再清 MOE/AOE、六路使能和计数器 |
| `pwm_emergency_stop()` | 致命异常关断，先写 GPIO BRR 拉低 SD，再清 TIM1 输出及计数器，不依赖 HAL 句柄或延时 |

### 启动与联锁

当前 G474 的开桥策略禁止使能。保留的六步驱动路径供后续验证，启动流程为：关桥 → 停 PWM → 等 200 ms → 占空比清零 → pwm_start → 三相自检 → apply_step → 六步专用开桥检查。任一步拒绝开桥，应用退回 STOP。

两类联锁共用波形配置检查：MOE/CEN 有效、ARR=4250、PSC=0、RCR=1、中心对齐模式 1、CKD=1、DTG=149、OSSI/OSSR 有效、PWM1、CCR 预装载及主/互补输出高有效。三相自检要求使能掩码 0x555；六步入口要求指定两相的掩码精确匹配，避免“任意两相开了就通过”。

开桥前触发更新事件提交 CCR，避免使用上次运行或自检留下的占空比。该动作适用于当前软件触发 ADC 的 v0.1；后续改硬件触发时必须重新核对更新事件和采样时序。

使能 CCxE/CCxNE 是允许输出互补 PWM，不代表上下管同时导通。HAL_TIM_PWM_Start 只开启主输出，互补输出由 HAL_TIMEx_PWMN_Start 单独控制；本模块显式管理六路使能。单相悬空只改 CCER，不能调用会影响 MOE/计数器的 HAL 停机接口。

### 故障关断

NMI、HardFault、MemManage、BusFault、UsageFault 及 Error_Handler 在死循环前调用 pwm_emergency_stop。清除 AOE 是为了防止更新事件自动恢复 MOE。故障后保持停机直至系统复位；该函数不能处理 CPU 已完全失去执行能力的情况。

## 2. 电流采样：adc_cur

| 接口 | 返回值与约束 |
|---|---|
| `uint8_t adc_cur_init(void)` | 关桥时调用，句柄由平台管理；1 成功，0 失败，失败后保持关桥并复位重试 |
| `uint8_t adc_cur_read(adc_cur_sample_t *out)` | 1 成功；0 失败且 out 保持原值，不得使用旧样本 |

初始化：依次校准 ADC1/ADC2/ADC3，任一路失败保持未就绪。通道由 CubeMX 生成，分别为 PC0/IN6、PC1/IN7、PB1/IN1。

读取：依次软件启动每个 ADC 的规则组 → 轮询完成（超时参数 1 ms）→ 读取单通道结果 → 停止转换。仅三路全部成功才发布完整样本；任何失败不覆盖调用者的输出，应用关桥并锁住启动入口。

换算保持 `I=(raw×3.3/4095−1.25)/0.12`。HAL 自校准只校准 ADC 自身，不等于测量驱动板放大器零漂；真实 VDDA 和每相零偏仍待标定。

v0.1 每 500 ms 软件采样仅用于状态监视，未与下管采样窗口同步，不能当作可靠的瞬时相电流或快速过流保护。8 A 软件限流按维护者要求暂缓，后续需先完善同步采样。

## 3. 霍尔：hall

PC6/PC7/PC8 上拉输入，原始编码 U/V/W 分别位于 bit2/bit1/bit0。hall_read 返回原始编码 1～6，000/111 返回 HALL_INVALID；hall_state_str 用于打印原始状态。

调用顺序：hall_read → 排除 HALL_INVALID → hall_sector_deg。

| 原始编码 | 1 | 3 | 2 | 6 | 4 | 5 |
|---|---|---|---|---|---|---|
| 相对扇区角度 | 0° | 60° | 120° | 180° | 240° | 300° |

该表来自样例位序换算，证据见 [08-review-findings.md](08-review-findings.md)。S1 只是相对零点，实际方向和转子电角度偏移仍待标定；该角度函数当前未被开环控制调用。非法输入仍返回 0，不能仅凭角度值判断状态有效性。

## 4. 调试串口：bsp_uart

| 接口 | 功能 |
|---|---|
| `bsp_uart_init()` | 初始化静态发送队列并清 ORE |
| `bsp_uart_printf(fmt,...)` | 格式化日志并入队，不等待发送；单条最多 127 字节 |
| `bsp_uart_task()` | 每轮主循环最多发送一字节，硬件忙或队列空时立即返回 |
| `bsp_uart_read(out)` | 非阻塞收一字节并清接收溢出标志；1 收到，0 无数据或参数无效 |

发送队列容量 512 字节，保留一个空位区分满/空，最多缓存 511 字节。队列不足时丢弃整条日志，不能为了日志阻塞换相。全部接口仅由主循环调用，不可在 ISR 并发调用。格式化本身仍耗 CPU 时间，但不再等待串口线传输。

模式切换按要求阻塞等待 200 ms，此期间不会接收命令，连续输入仍可能丢失；清 ORE 只能恢复后续接收，不能恢复已经丢失的字节。后续可改成非阻塞恢复状态机。上电 PWM 自检的等待循环会继续发送日志。

## 5. 应用与已知限制

串口命令：0 停机，1/2 为正反转请求（当前拒绝），h 霍尔监视，+/- 调整占空比，>/< 调整电频率，? 打印帮助。帮助分条入队，避免超过格式化缓冲区。

六步表保持 U+V-、U+W-、V+W-、V+U-、W+U-、W+V-；只关当前悬空相，高相斩波、低相上管 0%。占空比范围 5%～60%，电频率 0.5～20 Hz。换相仍为毫秒级主循环调度，存在时间量化和任务抖动；尚无闭环、同步采样或软件限流。

硬件验证方法及本次软件验证结果见 [09-validation-and-maintenance.md](09-validation-and-maintenance.md)。
